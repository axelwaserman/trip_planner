<objective>
Land the migration's centerpiece: rewrite `ChatService.chat_stream` against PydanticAI `agent.iter()`, replace `search_flights`'s `_flight_client` module-attribute back-door with `RunContext[ChatDeps]`, and rewrite the `MockLLMStream` test fixture against PydanticAI's `FunctionModel`. Wire `InMemoryConversationStore` through `api/main.py`'s lifespan.

After this plan, the system runs end-to-end on PydanticAI:
- A FastAPI request reaches `ChatService.chat_stream`.
- It loads history via `await self._conversation_store.load(session_id)`, builds `ChatDeps`, and calls `agent.iter(message, message_history=history, deps=deps)`.
- The per-node loop yields `StreamEvent` subclasses (`ContentEvent`, `ThinkingEvent`, `ToolCallEvent`, `ToolResultEvent`, `ErrorEvent` on exception).
- After the `End` node, it appends `agent_run.result.new_messages()` via the store.
- The SSE wire bytes are byte-identical to Phase 4.7 (Wave 0 golden file enforces this).

LangChain imports STILL exist after this plan in two places — they are removed in Wave 4 (plan 05-05) along with `pyproject.toml`:
- `backend/app/chat/service.py` (any leftover `from langchain_core.messages import ...` is removed in this plan, BUT the `langchain` packages remain installed until Wave 4).
- `backend/tests/integration/test_chat_service_flow.py` — the LangChain history-shape assertions are rewritten to read from the `ConversationStore`.

Purpose: This is the single largest behavioral change in the phase. Every later wave is dependency cleanup or docs.
Output: ChatService + tool + lifespan + fixture all rewritten; integration tests rewired against the new fixture; manual UAT recommended after this plan completes.
</objective>
