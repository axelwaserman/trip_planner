<objective>
Rewrite each of the four concrete LLM providers against PydanticAI's `Model` + `Agent` surface, replacing the LangChain `bind_tools` body with a `build_agent` body. Each provider explicitly subclasses `LLMProvider` (the ABC) per D-03. Update `LLMProviderFactory.build()` to thread the new `Settings.openai_o_series_model_prefixes` knob into `OpenAIProvider`. (Note: `app/llm/protocol.py` was already deleted in Wave 1 / Plan 05-02 Task 1; the four providers already import from `app.llm.base` and their `bind_tools` return-type annotations were already retyped to `Any` in Wave 1 — Wave 2 deletes the bodies.)

**Wave 2 entry condition (Task 0):** Before any provider rewrite touches `from pydantic_ai import ...`, this plan's Task 0 runs the package legitimacy gate (blocking-human checkpoint per the GSD planner) and then `uv add 'pydantic-ai>=0.8.1'` so subsequent tasks can import the package. The corresponding `uv remove langchain* + langgraph` step REMAINS in Wave 4 / Plan 05-05 — only the `uv add` half moves forward to Wave 2 (closes hidden ordering dependency D7).

Critical invariants preserved across the rewrite:
1. `validate_config()` body for every provider — UNCHANGED (still uses `httpx` for `/api/tags`, `/v1/models`, presence-only key checks). The `httpx` exception to ADR-008 is documented in RESEARCH.
2. `list_models()` body for every provider — UNCHANGED.
3. The Phase 4.5 Pitfall 2 defensive `assert self._api_key is not None` for Anthropic — preserved as Pitfall 4 (RESEARCH).

Critical rewrites:
1. Drop `from langchain_*` imports across all four providers.
2. Drop `bind_tools(tools) -> BoundProvider` method; replace with `build_agent(tools, deps_type) -> Agent[Any, str]`.
3. Each provider explicitly subclasses `LLMProvider` (D-03).
4. Drop `SecretStr` wrapping (PydanticAI takes plain `str`).
5. Drop the `_model_supports_reasoning` private method on Ollama and the `reasoning_model_prefixes` constructor param (RESEARCH OQ-04).
6. Drop the `"lm-studio"` `SecretStr` sentinel.
7. Add `o_series_prefixes` constructor param to `OpenAIProvider` (sourced from `Settings.openai_o_series_model_prefixes` via the factory).

Purpose: Provide concrete PydanticAI-backed providers so Wave 3 can rewrite ChatService against `agent.iter()`.
Output: 4 in-place rewrites of provider files, 1 in-place edit of factory.
