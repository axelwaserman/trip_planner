|----------|-------------|
| GitHub Actions secrets → CI runner env | `AMADEUS_API_KEY` and `AMADEUS_API_SECRET` are surfaced as env vars in the `amadeus-e2e` job only; GitHub's secret-redaction masks them in logs. |
| Local dev `.env` → process | Same env-var surface as CI; covered by `SecretStr` (Plan 02) and `ApiKeyScrubber` (existing). |
| Real Amadeus sandbox API → e2e tests | Outbound HTTPS via pyreqwest; no untrusted input crosses INTO the process from this boundary in v1 (we only consume the response). |

The four-test suite issues ~3 token fetches and ~3 search calls — well within Amadeus sandbox quotas (typically 10 req/sec). The `pybreaker` defaults (Plan 03) prevent runaway request storms. |
| T-07-SC | Tampering (supply chain) | No new packages | n/a | This plan adds no new Python dependencies. GitHub Actions versions used (`actions/checkout@v4`, `setup-python@v5`, `astral-sh/setup-uv@v4`, `actions/cache@v4`) are pinned and match the existing workflow. |
