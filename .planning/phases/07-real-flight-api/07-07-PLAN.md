Close the two BLOCKER defects in `backend/app/flights/amadeus_client.py` flagged by Phase 7 verification (07-VERIFICATION.md, status `gaps_found`, score 23/25 truths verified):

- **CR-01** — `search()` and `_search_impl()` double-apply `offset`, silently dropping un-fetched results for any `offset > 0`. No regression test drives `offset > 0`, which is exactly how the bug slipped through.
- **CR-02** — `_refresh_token` lacks `error_for_status(True)` on the OAuth POST and has no `StatusError` branch. A 401 (bad creds) raises `KeyError("access_token")`, gets caught by the catch-all `except Exception`, and is wrapped as `APIError(retryable=True)`. tenacity then retries up to 3× against bad credentials. The e2e test `test_error_mapping_401_with_bad_credentials` asserts `pytest.raises(APIError)` and so regression-locks the bug instead of the contract.

Both defects are localized to one production file plus three test files. WR-01..WR-07 and IN-01..IN-05 are deferred per the verification report — this plan stays tight on CR-01 + CR-02.

Purpose: Once these two defects close, D-11 ("HTTP status mapping holds end-to-end" + "non-429 4xx → retryable=False") is verified end-to-end and the `AmadeusFlightClient.search` pagination contract is honored.
