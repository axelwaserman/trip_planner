<objective>
Implement the real `AmadeusFlightClient` — the deliverable of REQ-real-flight-api. The client subclasses `FlightAPIClient`, performs OAuth2 client_credentials token fetch via pyreqwest (with an in-process cache + concurrent-refresh `asyncio.Lock` per D-01/D-02), composes the Plan 01 retry decorator over the Plan 03 circuit breaker over a pyreqwest GET against `/v2/shopping/flight-offers`, maps Amadeus HTTP status codes onto the existing `APIError` hierarchy (D-11), and reuses the existing `normalize_amadeus_offer()` (Phase 4.6) with one Pitfall-2 fix (UTC fallback on naive datetimes). All tests use `unittest.mock` at the pyreqwest boundary — no real HTTP traffic.

Purpose: This plan is the heart of Phase 7. It produces the real client that Plan 05's lifespan branch instantiates and Plan 06's e2e_amadeus tests exercise live. By splitting token cache, error mapping, and search composition into separate test files, each invariant is independently regression-locked.
Output: `backend/app/flights/amadeus_client.py` + Pitfall-2 fix in `flight_search.py` + 3 unit test files (search composition, token cache, error mapping). `pyreqwest>=0.12.0` declared.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02 | Information Disclosure | Token refresh failure path in `_refresh_token` | mitigate | Generic exception message `"Amadeus token refresh failed: {type(exc).__name__}"` — uses exception class name only, never the formatted exception text (which could include credentials echoed by Amadeus in some error shapes). The credentials live in `SecretStr` (Plan 02) and are accessed only via `.get_secret_value()` inside `_refresh_token` and never logged. The existing `ApiKeyScrubber` provides defense-in-depth on bytes that may have already concatenated. |
| T-07-03 | Information Disclosure | API error logging for non-token paths | mitigate | `_raise_from_http_status` constructs error messages from `status` only — no body inspection that might echo a credential. Verified by `test_raise_from_http_status` parametrize. |
| T-07-04 | Denial of Service | 401 token-refresh loop | mitigate | The 401 path invalidates the cache (`_access_token = None`) and raises `APIClientError(retryable=False)` so tenacity will NOT auto-retry — the user-driven next call gets a fresh token. Per OQ 1, this caps the loop at 1 token refresh per user-driven call. Verified by `test_search_401_invalidates_token_cache`. The `pybreaker` layer (Plan 03) bounds runaway retries against any failure mode. |
| T-07-SC | Tampering (supply chain) | `pyreqwest` install | mitigate | Per RESEARCH.md `## Package Legitimacy Audit`, `pyreqwest` is `[OK]` (~1 yr old, source repo `github.com/MarkusSintonen/pyreqwest`, slopcheck OK). ADR-008 mandates pyreqwest for outbound HTTP — alternative libraries (httpx, aiohttp, requests) are explicitly forbidden. No human checkpoint required. |
