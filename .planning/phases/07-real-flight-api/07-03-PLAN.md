<objective>
Create the async-safe circuit breaker helper that Plan 04's `AmadeusFlightClient` will compose with. Per RESEARCH Pattern 3 / Pitfall 4 (verified live in research): pybreaker's `@cb` decorator does NOT correctly trip on async functions — it wraps the synchronously-returned coroutine, never sees the awaited exception, and the failure counter stays at 0. The correct pattern uses `state.before_call()` → `await coro_fn(...)` → `state._handle_success()` / `state._handle_error()` directly. This plan implements that helper, adds `pybreaker` as a pinned dependency, and locks the async-safety invariant with tests including a regression test for the decorator anti-pattern.

Purpose: Plan 04's `AmadeusFlightClient.search` calls `call_with_breaker(self._breaker, self._search_impl, query, ...)`. Building this helper as its own plan lets Plan 04 focus on Amadeus-specific logic and keeps the async-safety pitfall tested in isolation.
Output: New module `backend/app/tools/circuit_breaker.py` exporting `call_with_breaker`, new test file with ≥ 3 tests, `pybreaker>=1.4.1,<2.0` in `pyproject.toml`.
</objective>

```
async def call_with_breaker(
    breaker: pybreaker.CircuitBreaker,
    coro_fn: Callable[..., Coroutine[Any, Any, T]],
    *args: Any,
    **kwargs: Any,
) -> T: ...
```

Behavior contract:
- Calls `breaker.state.before_call(coro_fn, *args, **kwargs)` first; this raises `CircuitBreakerError` synchronously when the circuit is open.
- Awaits `coro_fn(*args, **kwargs)`.
- On exception: if `breaker.is_system_error(exc)` is True, calls `breaker.state._handle_error(exc, reraise=False)` (which increments the failure counter and may trip the circuit), then re-raises the original exception.
- On success: calls `breaker.state._handle_success()` and returns the awaited value.
- pybreaker's `_handle_error` is a single-underscore "protected" method — pin `pybreaker<2.0` and add a `# noqa: SLF001` comment with rationale.

From backend/app/exceptions.py (consumers map `CircuitBreakerError` to APIError in Plan 04):
- `APIServerError(message, retryable=True)` is the type Plan 04 will raise from `CircuitBreakerError`.
