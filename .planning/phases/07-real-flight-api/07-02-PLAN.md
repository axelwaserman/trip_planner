## Trust Boundaries

| Boundary | Description |

| Environment → process | `AMADEUS_ENV`, `AMADEUS_API_KEY`, `AMADEUS_API_SECRET` env vars cross from the host into the Python process; pydantic validation is the gate. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | `Settings.amadeus_env` (drives base URL selection in Plan 03) | mitigate | `Literal["test","prod","mock"]` rejects any other value at construction time. Verified by `test_amadeus_env_rejects_invalid_value`. The downstream lifespan branch (Plan 03) maps the literal to a hardcoded base URL — no user-controlled URL is ever constructed. |
| T-07-02 | Information Disclosure | `Settings.amadeus_api_key`, `Settings.amadeus_api_secret` | mitigate | `SecretStr` redacts the value in `__repr__` / `__str__`. Verified by `test_amadeus_api_key_secretstr_scrubs_str`. The existing `ApiKeyScrubber` provides defense-in-depth on log records that may have already concatenated the key into a message string. `.get_secret_value()` is called only inside `lifespan` (Plan 03), never in logging paths. |
| T-07-SC | Tampering (supply chain) | New imports added to config.py | accept | No new packages added — `pydantic` (for `SecretStr`) and `typing` (for `Literal`) are already in `pyproject.toml`. No legitimacy gate required. |
