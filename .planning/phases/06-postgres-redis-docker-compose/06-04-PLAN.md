<objective>
Wire the new ABCs into ChatService and the FastAPI lifespan; replace `EnvUserRepository` with `PostgresUserRepository`; delete the env-seed user store and the obsolete `ConversationStore` shim. After this plan lands, the running app talks to Postgres for users, conversations, and messages — there is no in-memory user dict and no in-memory conversation store in the boot path.

Purpose: This is the integration-and-deletion plan. CONTEXT.md D-07 requires `EnvUserRepository` to be deleted in Phase 6, and the Phase 5 verification CR-04 requires `ChatService` to stop peeking into `_store`. Both happen here. The new auth bootstrap relies on Plan 06's `just db-seed` to populate the `user` table — but the rewire itself is independent and can ship first.
Output: rewired ChatService, deleted EnvUserRepository, new PostgresUserRepository, lifespan changes, end-to-end persistence test, login-against-PG integration test, lifespan-engine-dispose teardown test.
</objective>
