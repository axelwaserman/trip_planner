## Decisions Made

- **Composite unique index uses string column names, not class descriptors.** `Index("message_conv_seq", "conversation_id", "seq", unique=True)` inside `__table_args__` instead of `Index("message_conv_seq", Message.conversation_id, Message.seq, unique=True)` after the class. Class descriptors carry the Python annotation type (UUID, int), not a SQLAlchemy Column, so the descriptor form fails `mypy --strict`. Column-name strings bind at metadata build time and match alembic's autogenerated DDL exactly. Documented inline in `app/db/models.py`.
- **`alembic.ini` ships with blank `sqlalchemy.url`.** `env.py` is the single canonical place the URL is set at runtime (`config.set_main_option('sqlalchemy.url', settings.database_url)`). Documented in the .ini comment so a future contributor doesn't paste a literal URL there.
- **`__table_args__` for `Message`'s composite index, not module-level `Index(...)`.** Both are valid SQLAlchemy idioms but `__table_args__` keeps the constraint declaration adjacent to the class definition — less risk of moving the table without moving the index.
- **Test isolation via `DatabaseJanitor`, not `postgresql` connection-chained fixture.** Plan suggested `pg_database_url(postgresql_my_proc, postgresql)` chaining off the connection fixture. `DatabaseJanitor` is the underlying mechanism and offers cleaner per-test dbname assignment (`f"test_phase06_{id(postgresql_my_proc)}"`) without a still-open libpq connection holding the template database. Same outcome; cleaner control.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] script.py.mako missing `sqlmodel` import**
- **Found during:** Task 2 (running `alembic upgrade head` for the first time)
- **Issue:** The autogenerated migration body references `sqlmodel.sql.sqltypes.AutoString(length=120)` for SQLModel-typed columns, but alembic's default `script.py.mako` does not import `sqlmodel`. First `alembic upgrade head` raised `NameError: name 'sqlmodel' is not defined`. This is a known sqlmodel + alembic gotcha.
- **Fix:** Added `import sqlmodel  # noqa: F401` to `migrations/script.py.mako` (the canonical fix — every future migration ships correct), AND patched the existing `eaba5b7deda2_phase_6_initial_schema.py` to add the import inline.
- **Files modified:** `backend/migrations/script.py.mako`, `backend/migrations/versions/eaba5b7deda2_phase_6_initial_schema.py`
- **Verification:** `cd backend && uv run alembic upgrade head` now succeeds; `alembic check` reports "No new upgrade operations detected".
- **Committed in:** Task 2 commit (`ae725cb`).

**2. [Rule 1 - Bug] Composite Index used class descriptors → mypy strict failure**
- **Found during:** Task 1 (`uv run mypy app/db/models.py`)
- **Issue:** RESEARCH §"Conversation + Message + User SQLModel tables" code block declares the unique index as `Index("message_conv_seq", Message.conversation_id, Message.seq, unique=True)`. Under `mypy --strict`, the descriptors are typed as their Python annotations (UUID, int), not `Column`, so `Index(...)`'s argument type-checks fail.
- **Fix:** Switched to string-based column lookup inside `__table_args__`: `__table_args__ = (Index("message_conv_seq", "conversation_id", "seq", unique=True),)`. The result is byte-equivalent in alembic's autogenerated DDL.
- **Files modified:** `backend/app/db/models.py`
- **Verification:** `uv run python -c "...assert any(idx.name == 'message_conv_seq' and idx.unique for idx in m.indexes)..."` passes; alembic autogenerate emits `op.create_index('message_conv_seq', 'message', ['conversation_id', 'seq'], unique=True)` verbatim; `mypy app/db/models.py` reports zero issues.
- **Committed in:** Task 1 commit (`068fd39`).

**3. [Rule 3 - Blocking] env.py import order tripped ruff isort**
- **Found during:** Task 2 (`uv run ruff check migrations/env.py`)
- **Issue:** I initially placed `from alembic import context` BEFORE the SQLAlchemy imports to keep alembic + app imports grouped. ruff isort wants `alembic` sorted alphabetically with the other third-party imports.
- **Fix:** Reordered imports per `ruff --fix`. The CRITICAL ordering — `from app.db import models` BEFORE the `target_metadata = SQLModel.metadata` assignment — is preserved (the model import is still before the assignment, just with isort-sorted neighbour imports above it).
- **Files modified:** `backend/migrations/env.py`
- **Verification:** `uv run ruff check migrations/` and `uv run mypy migrations/` both pass.
- **Committed in:** Task 2 commit (`ae725cb`).

**4. [Rule 1 - Bug] conftest.py `object`-typed fixture parameter failed mypy strict**
- **Found during:** Task 3 (`uv run mypy tests/integration/db/`)
- **Issue:** The plan's `pg_database_url(postgresql_my_proc, postgresql)` signature uses untyped fixture params; under `mypy --strict` this fails because `object` (mypy's default) has no `.user`, `.password`, etc. attributes.
- **Fix:** Imported `pytest_postgresql.executor_noop.NoopExecutor` and used it as the explicit type for `postgresql_my_proc`. Also dropped the chained `postgresql` parameter — DatabaseJanitor manages the per-test database lifecycle directly without needing the connection fixture.
- **Files modified:** `backend/tests/integration/db/conftest.py`
- **Verification:** `mypy tests/integration/db/` reports zero issues; the round-trip test still passes in ~2s.
- **Committed in:** Task 3 commit (`9b78eda`).
