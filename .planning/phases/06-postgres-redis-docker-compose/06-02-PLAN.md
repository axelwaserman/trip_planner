## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Backend process → Postgres TCP (alembic + integration tests) | Schema changes execute against a live DB; FK + ON DELETE CASCADE constraints enforce ownership |
| `migrations/env.py` → `Settings` | DB URL crosses an importable Python boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02-01 | Tampering | `app/db/models.py` schema definitions | mitigate | SQLModel typed columns + parameterized binds prevent SQL injection at the ORM layer (RESEARCH §Security Domain). All FK columns declare `ondelete="CASCADE"` so deleting a `user` row cannot orphan `conversation` / `message` rows (V4 Access Control). |
| T-06-02-02 | Information Disclosure | `migrations/env.py` printing connection URL | mitigate | env.py reads `settings.database_url` but does NOT log it. The default alembic logger configuration only logs operation names, not URLs. Note for Plan 06: ensure `database_url` (with password) is added to log scrubbing patterns when the lifespan starts up. |
| T-06-02-03 | Elevation of Privilege | Composite unique `(conversation_id, seq)` index | mitigate | Prevents replay-stream tampering — two writers cannot insert the same `seq` for a single conversation; unique-violation surfaces to caller (Pitfall 6). Plan 03 owns the catch-and-emit error handling. |
| T-06-02-04 | Repudiation | alembic migration history | mitigate | Initial migration is committed to git with the model definitions; future schema changes land as new revisions, preserving an auditable schema-evolution log. `compare_type=True` flag in env.py detects column-type drift. |
| T-06-02-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan; pyproject already pinned in Plan 01. Audit table covers them. |
</threat_model>
