# Phase 4.6 Plan 01: Vendor-Neutral Tool JSON Summary

**One-liner:** Replaced search_flights() formatted-text return with FlightSearchResult JSON envelope using Pydantic v2 models, mock adapter, and Amadeus/Skyscanner normalization functions — schema locked for Phase 7 real API client without rework.

## What Was Built

### Models added to `app/models.py`

Seven new Pydantic v2 models inserted between `Flight` and `# Chat API Models`:

| Model | Purpose |
|-------|---------|
| `FlightEndpoint` | Departure/arrival point: IATA code, city, terminal (optional), tz-aware datetime |
| `CarrierInfo` | Carrier: 2-letter IATA code + display name |
| `PriceInfo` | Price: Decimal amount + currency; float→Decimal via `str()` coercion |
| `FlightSegment` | Single flight leg: endpoints, carrier, flight number, ISO 8601 duration, stops |
| `FlightResult` | Bookable offer: segments[], total_duration, price, booking_class (str) |
| `FlightSearchQuery` | Echo of request parameters included in envelope |
| `FlightSearchResult` | Canonical envelope: status, query, results[], count |

### Functions added to `app/tools/flight_search.py`

| Function | Signature | Purpose |
|----------|-----------|---------|
| `_extract_carrier_iata` | `(flight: Flight) -> str` | Extracts 2-letter IATA from flight_number prefix; "ZZ" fallback |
| `_to_iso_duration` | `(minutes: int) -> str` | Converts minutes to ISO 8601 (e.g. 330 → "PT5H30M") |
| `_to_flight_search_result` | `(flights: list[Flight], query: FlightQuery) -> FlightSearchResult` | Mock adapter: one FlightResult per Flight |
| `normalize_amadeus_offer` | `(offer: dict, dictionaries: dict) -> FlightResult` | Amadeus FlightOffer → FlightResult; resolves carrier name from dictionaries |
| `normalize_skyscanner_itinerary` | `(itin: dict) -> FlightResult` | Skyscanner itinerary → FlightResult; uses Decimal(str()) for price |

The tool's formatted-text return (`"\n".join(result_lines)`) was replaced with `result.model_dump_json()`. Error paths (FlightSearchError, Exception) remain as plain strings. `chat.py` is unchanged.

### Tests added in `tests/unit/test_tool_json_normalization.py`

10 tests covering all normalization scenarios:

1. `test_to_iso_duration_basic_cases` — 0, 60, 90, 330 minutes
2. `test_extract_carrier_iata_from_flight_number` — prefix extraction + "ZZ" fallback
3. `test_flight_search_result_envelope_shape` — {status, query, results, count} keys
4. `test_to_flight_search_result_preserves_flight_fields` — price, IATA, carrier, booking_class uppercase
5. `test_to_flight_search_result_empty_list` — empty envelope (status="ok", count=0)
6. `test_amadeus_offer_normalizes_without_lossy_collapse` — price, terminals, carrier name, booking_class
7. `test_amadeus_offer_carrier_name_comes_from_dictionaries` — carrier.name != carrier.iata_code
8. `test_skyscanner_itinerary_normalizes_without_lossy_collapse` — price, IATA, carrier, stops
9. `test_skyscanner_price_decimal_precision` — float 450.50 → Decimal("450.50") exactly
10. `test_search_flights_returns_json_envelope_string` — async; ainvoke() returns valid JSON

Google Flights fixture explicitly omitted with documented rationale (no public REST API).

## Known Stubs

`FlightEndpoint.city` uses the IATA code as a placeholder in the mock adapter (`_to_flight_search_result`). This is **intentional and documented** — `MockFlightAPIClient` does not carry city names. Phase 7's Amadeus client will populate the city field from `dictionaries.locations[iataCode].cityCode`. The field is non-optional in the model to ensure Phase 7 can fill it without a breaking change.
