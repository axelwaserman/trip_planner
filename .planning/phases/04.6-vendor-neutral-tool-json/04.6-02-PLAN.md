<objective>
Add a structured renderer to `ToolExecutionCard` that detects `FlightSearchResult`
JSON in `resultMetadata.full_result` and renders it as a Chakra UI v3 `<Table>`
plus labelled query/count sections — instead of dumping the JSON string through
`ReactMarkdown`. Preserve the existing `ReactMarkdown` path as a graceful fallback
for non-JSON tool results, error strings, and any future tool result shape.

Purpose: Without this change, the user would see `{"status":"ok","query":...}`
as raw text in the chat. The structured card makes flight results legible at a
glance while still letting the LLM narrate naturally in prose alongside.

Output:
- New TypeScript interfaces in `frontend/src/types/chat.ts`:
  FlightEndpointData, CarrierInfoData, PriceInfoData, FlightSegmentData,
  FlightResultData, FlightSearchQueryData, FlightSearchResultData
- `ToolExecutionCard.tsx` gains a `FlightResultsTable` subcomponent +
  `isFlightSearchResult()` type guard; the expandable results section now
  branches on JSON.parse + type-guard before falling back to ReactMarkdown
- New unit tests at
  `frontend/src/components/__tests__/ToolExecutionCard.test.tsx` covering
  structured render, markdown fallback, and tool-call argument rendering
</objective>
