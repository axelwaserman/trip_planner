    Section: Stack Overview

    - React 19 + TypeScript (strict mode)
    - Chakra UI v3 from @chakra-ui/react
    - Vitest + React Testing Library

    Section: Project Structure
    - src/components/ — UI components (ChatInterface, Sidebar, ProviderCard, ToolExecutionCard, ThinkingCard)
    - src/hooks/ — state and streaming hooks
    - src/types/ — TypeScript type definitions (chat.ts is the wire contract)
    - src/lib/ — utilities (parseSSE.ts)
    - src/theme/ — Chakra theme customization

    Section: Hook Conventions
    - useChat: primary hook for session lifecycle + SSE streaming; returns {messages, sendMessage, sessionId, isStreaming, ...}
    - useSSEStream: low-level raw SSE reader; wraps EventSource with fetch + ReadableStream
    - parseSSELine / parseSSE: parse raw SSE text into ChatStreamEvent discriminated union
    - useSessions: session list management
    - useProviderRefresh: provider discovery refresh

    Section: Type Definitions (types/chat.ts)
    - ChatStreamEvent discriminated union: ContentEvent | ThinkingEvent | ToolCallEvent | ToolResultEvent | ErrorEvent
    - Message: { role: MessageType, content: string, toolExecution?: ToolExecution }
    - MessageType: 'user' | 'assistant' | 'thinking' | 'tool_execution'

    Section: Chakra UI v3 Patterns
    - Semantic tokens: bg.canvas (page background), bg.surface (card/panel), fg.primary (body text), fg.secondary (muted text), fg.muted (placeholder), accent.solid (primary action), border.subtle (dividers)
    - colorPalette NOT colorScheme (v3 breaking change from v2)
    - Menu.Item requires unique value prop
    - Slot recipes for compound components

    Section: Vitest Setup
    - Config: frontend/vitest.config.ts
    - Setup file: frontend/src/test-setup.ts
    - Coverage: @vitest/coverage-v8
    - Run: cd frontend && npm test (watch) or npm test -- --run (single pass)
    - Coverage: cd frontend && npm run test:coverage

    Section: Known Pitfalls
    - Do not use colorScheme= on Chakra v3 components — use colorPalette=
    - Do not hardcode raw palette values (gray.50, blue.500) — use semantic tokens
    - Menu.Item value prop must be a unique string
    - useChat is a large hook (~1000 lines); edits must not break the re-entrancy guard at `getSessionSnapshot(sessionId).isStreaming`
    - Vite proxy at /api/* is configured in vite.config.ts — no absolute URLs in frontend API calls
