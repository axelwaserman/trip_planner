# Phase 4.9 Plan 04: Settings URL Validation + Refresh Cache Bypass Summary

**One-liner:** Client-side base URL validation with inline Chakra Field.ErrorText in ProviderCard, and unconditional model refresh in POST /api/providers/refresh bypassing TTL gating.

## What Was Built

### Task 1: ProviderCard URL Validation

Added client-side URL validation to `ProviderCard.tsx`:

- `validateBaseUrl(url: string): string | null` function at module scope: validates protocol is `http:` or `https:`, validates hostname is one of `localhost`, `127.0.0.1`, or `host.docker.internal`. Empty string returns `null` (valid — use default). Parse failures return `'Invalid URL format'`.
- `baseUrlError` state (`useState<string | null>(null)`) inside the component.
- `handleSave` now: clears error, validates URL for local providers when non-empty, returns early if invalid (prevents navigation to /app).
- `Field.Root` gets `invalid={!!baseUrlError}` prop; shows `Field.ErrorText` when error is set, falls back to `Field.HelperText` otherwise.
- Error clears on input change for immediate UX feedback.

### Task 2: Unconditional Refresh Endpoint

Updated `refresh_providers` in `routes.py`:

- Removed stale-filter computation: `stale = [name for name in _LOCAL_PROVIDER_NAMES if ...]`
- Removed TTL-gated conditional: `if stale: fresh = await factory.refresh_local_models()`
- Replaced with unconditional: `fresh = await factory.refresh_local_models()` that updates all entries.
- Removed unused `ttl` variable assignment.
- Updated docstring to clearly document the GET vs POST TTL semantics.
- Updated test: `test_refresh_respects_cache_ttl` → `test_refresh_bypasses_cache_ttl` to assert the new behavior (refresh_local_models always called, fresh models returned even when cache appears valid).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Updated test for removed TTL behavior**
- **Found during:** Task 2 verification
- **Issue:** `test_refresh_respects_cache_ttl` was testing the old TTL-gated behavior that was intentionally removed. It asserted that `refresh_local_models` would NOT be called when the cache appeared fresh — the exact opposite of the new behavior.
- **Fix:** Renamed and rewrote the test as `test_refresh_bypasses_cache_ttl` to assert that `refresh_local_models` IS always called regardless of cache state, and the response reflects fresh data.
- **Files modified:** `backend/tests/unit/api/test_providers_refresh_route.py`
- **Commit:** 500af1f

**2. [Rule 2 - Enhancement] Clear error on input change**
- **Found during:** Task 1 implementation
- **Issue:** Plan showed error clearing only in `handleSave`. Without clearing on change, the red error state persists even while the user is typing a correction, which is poor UX.
- **Fix:** Added `if (baseUrlError) setBaseUrlError(null)` to the `onChange` handler.
- **Files modified:** `frontend/src/components/ProviderCard.tsx`
- **Commit:** b25ec71

**3. [Rule 2 - Enhancement] HelperText/ErrorText toggle**
- **Found during:** Task 1 implementation
- **Issue:** Plan showed `{baseUrlError && <Field.ErrorText>}` after the existing `<Field.HelperText>`. Having both simultaneously would show helper text and error text together.
- **Fix:** Used a ternary so either `Field.ErrorText` or `Field.HelperText` shows, never both.
- **Files modified:** `frontend/src/components/ProviderCard.tsx`
- **Commit:** b25ec71
