# Phase 04.7 Plan 01: Chat Package Refactor + StreamEvent Discriminated Union Summary

Refactored `backend/app/chat.py` into an `app/chat/` package, replaced the monolithic `StreamEvent` Pydantic class with a discriminated union of 5 concrete event models, wired `ErrorEvent` into `ChatService.chat_stream()` for tool-execution exceptions with log-scrubbed `raw_detail`, and stored `last_tool_invocation` on session metadata for the retry endpoint.

## What Was Built

**`backend/app/chat/models.py`** — ErrorCode StrEnum with 3 wire-level codes (`session_error`, `tool_error`, `stream_error`) + 5 concrete event Pydantic models each carrying only their own fields + a `StreamEvent` Annotated discriminated-union alias (not a class). Follows the `ProbeErrorCode` + `ProbeError` pattern from `app/llm/errors.py` exactly.

**`backend/app/chat/service.py`** — ChatService extracted verbatim from `app/chat.py` with 3 targeted changes:
1. `_metadata` widened to `dict[str, dict[str, Any]]` (was `dict[str, dict[str, str]]`)
2. All `StreamEvent(type=...)` yields replaced with concrete class yields
3. Tool execution wrapped in `try/except APIError` + `except Exception` blocks yielding `ErrorEvent` with `_scrub(str(exc))` as `raw_detail`; `last_tool_invocation` stored after each `ToolCallEvent` yield

**`backend/app/chat/__init__.py`** — Re-exports `ChatService` + all 7 event symbols; preserves `from app.chat import ChatService` compatibility for all 5 existing consumers unchanged.

**Routes.py changes** — `ValueError` handler now yields `ErrorEvent(session_error, ...)` and `Exception` handler now yields `ErrorEvent(stream_error, ...)` instead of the old `StreamEvent(type="content")`.
