## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| chat_stream → SSE wire | Tool exception text crosses here; raw_detail must pass through `_scrub` first to redact API-key-shaped substrings. |
| _metadata read/write | Only the route layer (Plan 02) gates ownership; service.py treats the dict as already-trusted (matches existing CR-02 pattern). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04.7-01 | Information Disclosure | `ErrorEvent.raw_detail` from upstream APIError text | mitigate | Always wrap `str(exc)` in `_scrub(...)` at every yield site (3 except branches in chat_stream). Test_stream_events asserts the scrubbing happens. |
| T-04.7-02 | Tampering | `last_tool_invocation` overwrite mid-stream | accept | Single-stream-per-session is enforced by useChat re-entrancy (frontend), and the metadata dict is per-session keyed; concurrent overwrite has no security impact (only the latest invocation is retried). |
| T-04.7-03 | Information Disclosure | New ErrorEvent fields leak internal codes via wire | accept | error_code values (`tool_error`, `session_error`, `stream_error`) are intentionally generic; tool_name + scrubbed raw_detail are the only potentially-sensitive fields and both are user-actionable. |
</threat_model>
