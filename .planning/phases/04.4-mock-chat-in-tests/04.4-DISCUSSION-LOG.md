**Notes:** No follow-up clarification needed.

### Chunk taxonomy scope clarification

User asked to "revamp the data structures used to yield the four chunk kinds to the frontend." This prompted a three-layer disambiguation:
- Layer 1 (SSE wire `StreamEvent`) → Phase 4.7
- Layer 2 (ChatService internal LangChain shapes) → Phase 6
- Layer 3 (mock chunk dataclasses) → **this phase only**

**User's choice:** Layer 3 only (mock chunk shape)

### tool_result chunk gap

| Option | Description | Selected |
|--------|-------------|----------|
| Three chunks only: Content / Thinking / ToolCall | Honors actual LLM contract; tool_result comes from ChatService running real tool | ✓ |
| Four chunks + synthetic ToolResult | Lets tests assert tool_result without real tool; adds second mock seam | |
| Three chunks + separate tool stub helper | Clean separation; two helpers to learn | |

**User's choice:** Three chunks: Content / Thinking / ToolCall
**Notes:** tool_result SSE events are asserted end-to-end through ChatService + MockFlightAPIClient.

### Chunk data structures

Not presented as a formal question — decided during chunk-taxonomy deep-dive: frozen dataclasses forming a discriminated union (`Chunk = Content | Thinking | ToolCall`). Immutable per coding-style rules, mypy-strict compatible, adapter isolates LangChain dependency.
