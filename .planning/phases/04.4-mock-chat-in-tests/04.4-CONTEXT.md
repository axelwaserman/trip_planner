<decisions>
## Implementation Decisions

### Fixture API Shape

- **D-01: API style — pre-baked scenarios + builder hybrid.**
  Library exports both: small pre-baked helpers (`greeting_stream()`, `single_tool_call_stream(tool, args)`, `multi_turn_stream()`) for the 80% case, plus `MockLLMStream.from_chunks([...])` builder for one-off scenarios. Pre-baked keeps common tests one-line; builder unlocks the long tail without library changes.

- **D-02: Chunk taxonomy — three types only: `Content`, `Thinking`, `ToolCall`.**
  These map to what the LLM actually produces. `tool_result` SSE events are emitted by `ChatService` after running the real tool (`MockFlightAPIClient`, seeded), not by the LLM. Tests that want to assert `tool_result` events do so end-to-end through `ChatService` — the correct seam. No synthetic `ToolResult` chunk in the mock.

- **D-03: Chunk data structures — frozen dataclasses (discriminated union).**
  ```python
  @dataclass(frozen=True)
  class Content:
      text: str

  @dataclass(frozen=True)
  class Thinking:
      text: str

  @dataclass(frozen=True)
  class ToolCall:
      name: str
      args: dict[str, Any]
      id: str = "call_test"

  Chunk = Content | Thinking | ToolCall
  ```
  Immutable per global coding-style rule. Type-safe under mypy strict. `match`-friendly in the `MockLLM` adapter. Zero LangChain leak in test code — the adapter inside `MockLLM.astream()` translates each `Chunk` to a LangChain `AIMessageChunk` / `AIMessage`. Phase 6 rewrites the adapter only; test code doesn't change.

- **D-04: LLM seam — `MockLLM` class with `.astream()` / `.bind_tools()`.**
  A typed class structurally compatible with `BaseChatModel`. Tests do `ChatService(flight_client=..., llm=MockLLM(stream=...))`. Mirrors today's `MockChatModel` shape. Phase 6 swaps this class for a `MockAgent` shape against PydanticAI — one replacement, tests untouched.

- **D-05: Scope boundary — Layer 3 (mock chunks) only.**
  The SSE wire union (`StreamEvent`) is Layer 1 — Phase 4.7's job. `ChatService`'s internal LangChain shapes are Layer 2 — Phase 6's job. This phase owns Layer 3 (mock chunk API + adapter to LangChain).

### Migration

- **D-06: Delete `backend/tests/fixtures/mock_llm.py`; write `backend/tests/fixtures/llm.py` net-new.**
  `mock_llm.py` has zero callers in active tests. The new shape (frozen dataclasses + hybrid API) is structurally different enough that "rename" is misleading. Clean delete is the smallest diff.

- **D-07: Delete both `.skip` files.**
  `test_chat_service_mocked_llm.py.skip` and `.skip.bak` both reference `app.domain.chat`, `InMemorySessionStore`, `FlightService` — an architecture that was never built in this codebase. Imports would fail immediately if unskipped. Porting their test intent is handled by the new `test_chat_service_flow.py` written against today's `app.chat.ChatService`.

- **D-08: Single-file layout — `backend/tests/fixtures/llm.py`.**
  `MockLLM`, `Content`/`Thinking`/`ToolCall` dataclasses, `content()`/`thinking()`/`tool_call()` helpers, and pre-baked scenarios all in one file. ROADMAP names this exact path. Expected ~150 lines — well under the 400-line cohesion threshold. Revisit as a package if it grows.

### Chat Coverage

- **D-09: Scope — fixture + happy-path tool flow.**
  Ship `llm.py` AND the integration tests that prove it works against real `ChatService`. Not fixture-only (would leave ROADMAP SC#2 unverifiable) and not broad coverage (Phase 8 owns the coverage ratchet).

- **D-10: Three locked test scenarios.**
  - **content-only response** — user sends message; LLM emits 2-3 content chunks; no tool calls. Assert SSE emits content events only; history records user + AI messages.
  - **single tool call → final summary** — LLM emits `ToolCall` chunk; `ChatService` runs `MockFlightAPIClient` (seed=42, deterministic); second `astream()` emits content chunks. Assert: `tool_call` SSE event, `tool_result` SSE event with `elapsed_ms`, content events, history contains `HumanMessage` / `AIMessage(tool_calls)` / `ToolMessage` / `AIMessage`.
  - **multi-turn history retention** — two sequential `chat_stream()` calls in one session; second mock LLM response references prior turn. Assert second `astream()` receives the prior history in its `messages` argument.

- **D-11: Two-layer coverage — service layer + HTTP layer.**
  Direct `ChatService.chat_stream()` unit tests (tight feedback, fast). FastAPI `TestClient` integration tests (cover SSE serialization, auth header wiring). Some overlap is acceptable — each layer asserts what it owns.

- **D-12: `thinking + content` scenario deferred.**
  Not in the locked test list for this phase. Planner may add it if `thinking` chunk wiring proves trivial alongside the other scenarios. If not, it lands with Phase 4.5/4.7 test work.

### Test-Purpose Docs

- **D-13: Drop all four pytest markers (`unit`, `integration`, `e2e`, `slow`).**
  Phase 4.3 already removed `addopts = "-m 'not slow'"`. Path-based test selection is now the sole mechanism (`just test` → all tests, `just test-unit` → `tests/unit/`, etc.). Removing the marker declarations from `pyproject.toml` and the `@pytest.mark.*` / `pytestmark = [...]` calls from all test files eliminates the dead surface. The ability to do `pytest -m unit` ad-hoc is traded for a cleaner test API. Note: `pytest -m 'not e2e'` also stops working — not a current use case.

- **D-14: Collaborator-scope taxonomy for CLAUDE.md.**
  Expand the existing `### Test structure` section (~4 lines today) to ~15 lines describing:
  - `tests/unit/` — one module, all collaborators trivially constructed or `MagicMock`-ed; no FastAPI, no LLM stream, no HTTP.
  - `tests/integration/` — real FastAPI `TestClient` + real `ChatService` + `MockLLM` (from `fixtures/llm.py`) + `MockFlightAPIClient`; mocks live only at the I/O boundary.
  - `tests/e2e/` — real backend over HTTP, real auth flow; optionally real travel APIs gated on CI secrets; never a real LLM.
  README.md and `backend/tests/e2e/README.md` stay unchanged.

### Claude's Discretion

- Pre-baked scenario names (final choices between `greeting_stream()` / `no_tool_response()` / `conversational_reply()` etc.) — pick whichever names are clearest in context.
- Whether `MockLLM` inherits from `BaseChatModel` directly or uses a `Protocol`-compatible stub — either satisfies mypy strict; inherit is simpler, stub avoids the LangChain base class in test fixtures.
- New test file name: `test_chat_service_flow.py` (integration) + `test_chat_stream.py` (unit) is a reasonable split; planner may choose differently.
- Whether to also update `conftest.py`'s `mock_llm_provider` fixture to use `MockLLM` from `llm.py` instead of `MagicMock(spec=BaseChatModel)` — low risk improvement, not required.

</decisions>

## Existing Code Insights

### Reusable Assets
- `MockFlightAPIClient(seed=42)` (`backend/app/tools/flight_client.py`) — already deterministic; integration tests use `mock_flight_client` fixture from `conftest.py`. Tool-call scenario tests drive through the real tool + this client, so `tool_result` SSE events have deterministic content.
- `auth_headers` fixture (`conftest.py:12`) — JWT bearer token for HTTP-layer tests; already in use by `test_chat.py` and `test_session_probe.py`. New integration tests reuse it.
- `TestClient(app)` pattern (`test_chat.py:13`) — standard FastAPI test client with lifespan; new HTTP-layer tests follow same fixture shape.
- `InMemoryChatMessageHistory` (`app/chat.py:26`) — session history storage; multi-turn test asserts `list(history.messages)` directly on the service.

### Established Patterns
- **LangChain AIMessage chunk shape** (`app/chat.py:117-143`): thinking detected via `chunk.additional_kwargs.get("reasoning_content")`; tool calls detected via `isinstance(chunk, AIMessage) and chunk.tool_calls`. `MockLLM.astream()` adapter must emit the correct type for each branch.
- **Two-call astream() loop** (`app/chat.py:117` → `194`): first call streams initial response (possibly with `tool_calls`); second call (inside the tool branch) streams the final summary. `MockLLM` must handle being called twice; pre-baked `single_tool_call_stream` helper should encapsulate both sequences (or `MockLLM` accepts a `streams: list[...]` param for ordered calls).
- **AAA test structure** + descriptive names (`test_chat_service.py`, `test_session_probe.py`) — new tests follow the same naming convention: `test_chat_stream_emits_content_event_for_greeting`, `test_chat_stream_emits_tool_events_for_flight_query`, etc.
- **`pytest.mark.asyncio` stays** — `asyncio_mode = "auto"` in `pyproject.toml` means individual `@pytest.mark.asyncio` decorators are redundant but harmless; only remove the four *custom* markers (`unit`, `integration`, `e2e`, `slow`).

### Integration Points
- **`ChatService.__init__`** takes `llm: BaseChatModel` → `MockLLM` must satisfy this type annotation (inherit or be structurally compatible).
- **`conftest.py` `mock_llm_provider`** — currently returns `MagicMock(spec=BaseChatModel)`; consider updating to `MockLLM(stream=greeting_stream())` as a canonical default, but this is Claude's discretion (D-14).
- **`test_chat.py`** currently patches `ChatService.chat_stream` directly with a one-line stub — the new tests go deeper (drive through real `chat_stream()` via `MockLLM`). Both patterns can coexist in separate test files; `test_chat.py` tests HTTP wiring, new file tests chat-flow behavior.

## Specific Ideas

- The frozen-dataclass union (`Content | Thinking | ToolCall`) was explicitly chosen during discussion over `@classmethod` constructors and builder-only, for its immutability, mypy-strict compatibility, and clean Phase 6 migration path.
- User confirmed Layer 3 scope explicitly when asked about "revamping data structures" — the intent was mock chunk shape only, not SSE wire or ChatService internals.
- `tool_result` events are **not** a chunk the LLM produces — they come from `ChatService` invoking `MockFlightAPIClient`. Tests that assert `tool_result` events do so end-to-end through the service, not by injecting a mock chunk.
- All four pytest markers drop — path-only forever. User confirmed this explicitly when offered the option to keep `unit`/`integration`/`e2e` markers and drop only `slow`.

</specifics>
