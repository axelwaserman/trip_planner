The phase goal — *"The provider layer supports a real cloud LLM via API key and a dynamically-discovered local Ollama model, both selectable per session."* — is observably true in the codebase:

- Real cloud LLM via API key: `OpenAIProvider` and `AnthropicProvider` accept keys via env (`Settings.openai_api_key` / `Settings.anthropic_api_key`) or per-session payload (`SessionCreateRequest.api_key` → `SessionLLMConfig.api_key` → factory.build → provider constructor). Bound providers reach `api.openai.com` / `api.anthropic.com` (gated cloud tests confirm when env vars present).
- Dynamically-discovered local Ollama model: `OllamaProvider.list_models` hits `{base_url}/api/tags`. `factory.refresh_local_models` runs both local providers in parallel. `GET /api/providers` (lazy discovery) and `POST /api/providers/refresh` (explicit re-discovery) surface the live list to the UI.
- Selectable per session: Each `POST /api/chat/session` builds a fresh `SessionLLMConfig`, runs the per-provider probe, and stashes the resulting bound provider in `ChatService._bound_providers[session_id]`. There is no global bound LLM.
