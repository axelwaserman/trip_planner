# Phase 04.5 Plan 03: OllamaProvider Summary

OllamaProvider — local provider with dynamic `/api/tags` discovery, structurally implementing `LLMProvider` (no inheritance), wrapping `langchain_ollama.ChatOllama` with `reasoning=True` so qwen3 thinking tokens keep flowing through `chunk.additional_kwargs["reasoning_content"]` downstream.

## Outcome

- New subpackage `backend/app/llm/providers/` with `OllamaProvider` class.
- All four `LLMProvider` Protocol members implemented (`get_provider_name`, `validate_config`, `bind_tools`, `list_models`).
- 4.2 probe semantics migrated **verbatim** onto `OllamaProvider.validate_config` — same `ProbeErrorCode` values, same wire copy, only the `settings.ollama_base_url` substitution differs (`self._base_url`).
- `list_models` performs the dynamic-discovery success criterion (REQ-llm-provider-abstraction §6) by hitting `GET {base_url}/api/tags` and returning sorted unique ids, defensively unioning `entry["name"]` and `entry["model"]`.
- Wave-0 skip stubs in `tests/unit/llm/test_ollama_provider.py` replaced with 5 real AAA-pattern assertions covering all four `validate_config` branches plus `list_models` discovery.
