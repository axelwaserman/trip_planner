## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04.5-04-01 | Information Disclosure | api_key in OpenAIProvider repr/str | mitigate | self._api_key is a private attribute; no __repr__ or __str__ override exposes it. ChatOpenAI internally wraps it as Pydantic SecretStr (verified in RESEARCH.md). The provider class never logs it. |
| T-04.5-04-02 | Information Disclosure | api_key surfaced in pytest assertion failures | mitigate | Tests use the literal "sk-test" or "sk-x" — never a real key. |
| T-04.5-04-03 | Spoofing | Empty/whitespace key bypass | mitigate | validate_config rejects None AND empty-after-strip via `if not self._api_key` (truthy check covers both cases for str | None). |
| T-04.5-04-04 | Tampering | Provider name impersonation | accept | Factory (Plan 06) match-dispatches on the provider literal; this provider exposes get_provider_name() returning a literal string. No code path treats untrusted input as a provider name (Pydantic + match exhaustiveness in factory.build). |
</threat_model>
