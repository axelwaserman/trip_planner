# Phase 04.5 — UI Design Contract

> Visual and interaction contract for the LLM provider abstraction phase. Generated by `gsd-ui-researcher`, verified by `gsd-ui-checker`.
>
> **Stack pre-locked (do not re-ask):** React 18 + Vite + TypeScript, Chakra UI v3, react-router-dom v7, Lucide icons, Inter (body) + Fraunces (display) via Google Fonts. shadcn is **not** in use on this project — the design system is hand-rolled inside `frontend/src/theme/index.ts` and the Chakra v3 token surface.
>
> **Brand reference:** the editorial direction set by `pages/Login.tsx` + `components/auth/LoginForm.tsx` is the canonical pattern. This phase EXTENDS that direction onto a settings page + a sidebar; it does NOT invent new visual language.

---

## Phase scope (frontend surface area)

- New page: `pages/SettingsProviders.tsx` at route `/settings/providers`. Reachable from a new app-shell sidebar.
- New component: `components/Sidebar.tsx` (collapsible — chat list + "+ New chat" + "Settings" link).
- New component: `components/ProviderCard.tsx` (one per provider — Ollama, LM Studio, OpenAI, Anthropic).
- Modified: `components/ChatInterface.tsx` strips the in-header `<ProviderSelector />` dropdown; gains an active-provider/model **badge** (D-23).
- Modified: `lib/providerErrors.ts` adds `'invalid_api_key'` to the union and a switch case.
- Modified: `hooks/useChat.ts` reads the new `provider_settings` localStorage key and extends the session-create payload with `base_url` + `api_key`.
- Deleted: `components/ProviderSelector.tsx` (functionality moves to the settings page).

## Component contracts (interaction shape)

### `ProviderCard` (new — one per provider)

**States:** `needs_setup | ready | testing | unreachable | invalid_key`.

**Layout (vertical stack inside a `<Box bg="bg.surface" borderWidth="1px" borderColor="border.subtle" borderRadius="lg" p="6">`):**

```
[ category eyebrow                                     [status pill] ]
[ provider name (h2, Fraunces 24px) ]
[ subtitle copy (15px, fg.secondary) ]

[ optional: Base URL field (Field.Root + Input) ]
[ optional: API Key field (Field.Root + Input type=password + show/hide toggle) ]
[ Model field (Field.Root + native <select> styled to match Chakra Inputs) ]

[ Refresh models | Test connection (cloud only) ]    [ Use this provider ]
```

**Field rules:**
- API key input: `type="password"` by default, `Eye/EyeOff` toggle button (mirrors `LoginForm.tsx:98-111`). `autoComplete="off"`.
- API key display when populated: show last 4 chars only — `••••••••••••XHk2`. Replace on focus to allow paste.
- `paste` event accepted on the API key input — no `paste` prevention.
- Base URL input: `type="url"`. Default value pre-filled (e.g. `http://localhost:11434` for Ollama).
- Model selector: native `<select>` styled to match Chakra `<Input>` (matches existing `ProviderSelector.tsx:121-138` pattern). Disabled when models list is empty.
- Save button: `<Button colorPalette="accent">` (matches `LoginForm.tsx:120-128`). Label: `Use this provider`.
- Refresh button (local providers only): `<Button variant="ghost" color="accent.solid">Refresh models</Button>` with a `<RefreshCw size={14} />` icon, spins during the request (CSS animation only, not new motion library).
- Test connection button (cloud only): `<Button variant="ghost" color="accent.solid">Test connection</Button>` with a `<Plug size={14} />` icon. Disabled until key field has any value.

**Status pill (top-right of each card):**
- `Ready` — `bg="accent.muted"`, `color="accent.solid"`, with 8px `accent.solid` dot.
- `Needs setup` — `bg="bg.canvas"`, `color="fg.secondary"`, with 8px `border.strong` dot.
- `Unreachable` — `bg="danger.muted"`, `color="danger.solid"`, with 8px `danger.solid` dot.
- All three pills: `borderRadius="full"`, `px="3"`, `py="1"`, `fontSize="13px"`, `fontWeight="500"`.

**Validation feedback timing:**
- Field-level validation runs `onBlur`, not `onChange` (avoid noisy red borders while typing).
- Save button is disabled when required fields are empty for that provider.
- API key length cap (256 chars per RESEARCH.md security spec) enforced at backend; UI shows `Field.ErrorText` if backend rejects.
- Backend probe error after Save → renders inside the same card as a `SelectorErrorBanner`-shape inline alert (re-use the existing component verbatim).

## Motion

- Spinner on Refresh / Test buttons: CSS `@keyframes spin 1s linear infinite` on the icon. No JS motion library.
- Sidebar mobile overlay: 200ms `ease-out` transform (slide-in from left), backdrop fades 200ms.
- Toast enter/exit: 180ms `ease-out`, transform + opacity (Chakra v3 toaster defaults are fine).
- Skeleton shimmer: Chakra `<Skeleton />` default.
- **No** scroll-driven animation, no decorative particle/blob graphics, no parallax. The brand direction is editorial-minimal, not animated-luxury.

Respect `prefers-reduced-motion: reduce`: spinner freezes (icon shown static); skeleton shimmer disabled; toast enter/exit becomes instant.

## Persistence affordance — "session-only" framing

The deferred decision in CONTEXT.md ("does the key persist past the session?") is resolved at the UI layer **with a clear localStorage-only model in v1**. The UI MUST communicate this honestly:

- API key field helper text: `Stored in this browser only. Never sent to our server.`
- Sidebar helper under chat list: `Sessions reset when the server restarts.`
- A small `<Info size={12} />` icon next to the API key label opens a popover with: `Your key lives in this browser's localStorage. It travels to our server only on the next chat session, where it dies in process memory after the session ends. We never write it to disk.`
- When a phase-5 backend-encrypted-keys feature lands, this copy gets a one-word swap to `Stored encrypted on our server.` — the rest of the layout stays.
