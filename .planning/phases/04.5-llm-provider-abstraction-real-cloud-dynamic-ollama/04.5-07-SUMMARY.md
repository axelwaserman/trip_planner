## Decisions Made
- **F5 inlineCode is `[]`** — UI-SPEC §"Error states" row F5 explicitly says `(none — instead, the failing key field gets a danger.solid focus ring)`. RESEARCH.md §1033 mentions `inlineCode: [<key-input-id>]` as a possible alternative, but the PLAN action block locks `inlineCode: []`. UI-SPEC + PLAN are authoritative; RESEARCH.md is descriptive.
- **`loadProviderSettings()` returns `ProviderSettings | null`** — the cold-run path (neither key present) sends `null` for `base_url` and `api_key` so the backend factory's env-var precedence (D-08) is the authority. Returning a defaulted `ProviderSettings` record would have leaked the frontend-default `http://localhost:11434` onto the wire on cold runs, taking precedence over a (potentially different) backend-configured `OLLAMA_BASE_URL` env var.
- **Migration is one-shot read-and-overwrite (per D-21)** — legacy `'llm_provider_config'` is removed after migration; subsequent renders find `'provider_settings'` and skip the migration branch entirely. T-04.5-07-02 (legacy-key tampering) is mitigated by the guard order: only fires when `'provider_settings'` is absent AND `'llm_provider_config'` is present.

## Deviations from Plan

None — plan executed exactly as written.

The plan's optional `inlineCode: [<key-input-id>]` interpretation from RESEARCH.md §1033 was considered but rejected in favour of the explicit `inlineCode: []` instruction in the PLAN action block + UI-SPEC F5 row. This is not a deviation — it is the plan's primary direction.

## Issues Encountered

- **`npm test` failed with "vitest: command not found" on first run.** Root cause: this worktree did not yet have `node_modules/`. Resolved by running `npm install` (added 510 packages). Not a code issue; one-time worktree setup. Build verification then ran cleanly.
- **Initial GREEN attempt for the cold-run case sent `base_url: 'http://localhost:11434'` instead of `null`.** The `loadProviderSettings()` function originally always returned `DEFAULT_PROVIDER_SETTINGS` (which has a non-null base_url). Caught by the test "creates a session with defaults when localStorage is empty (D-24 payload shape)" — failure was the right signal. Fixed by changing the function to return `ProviderSettings | null` and short-circuiting the cold-run path in `useEffect` to send `null` directly, so the backend factory's env-var precedence (D-08) wins on cold runs.
