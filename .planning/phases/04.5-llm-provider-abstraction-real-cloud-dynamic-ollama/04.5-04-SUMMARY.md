## Deviations from PATTERNS.md

**One deviation, type Rule 3 (auto-fix blocking issue) — `SecretStr` wrap.**

PATTERNS.md §"backend/app/llm/providers/openai.py" line 304 shows:

```python
llm = ChatOpenAI(model=self._model, api_key=self._api_key)
```

passing the raw `str | None` key directly. RESEARCH.md noted "Pydantic SecretStr coerces" at runtime — true for runtime but not for `mypy --strict`, which sees `ChatOpenAI.api_key: SecretStr | Callable[[], str] | Callable[[], Awaitable[str]] | None` (the published `langchain_openai` 1.2.1 type signature) and rejects the plain `str`.

**Resolution (Rule 3):** wrap explicitly as `SecretStr(self._api_key)` when the key is non-`None`, propagate `None` otherwise. The exact construction:

```python
secret_key = SecretStr(self._api_key) if self._api_key is not None else None
llm = ChatOpenAI(model=self._model, api_key=secret_key)
```

This is strictly tighter than the pattern: same runtime behaviour, mypy-strict clean, and it doubles as a small reinforcement of D-09 (the wrapped `SecretStr` masks itself in any `repr()` / model-dump output). The pattern's `# type: ignore[return-value]` on the `bind_tools` return is preserved verbatim — `Runnable` structurally satisfies `BoundProvider` but mypy can't verify the duck typing across third-party Runnable generics.

No other deviations — class shape, message strings, hint text, curated list, and module docstring all match PATTERNS.md.
