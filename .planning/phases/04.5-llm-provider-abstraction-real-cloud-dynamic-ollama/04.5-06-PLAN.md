<objective>
Wire the per-session provider model end-to-end: the factory's match-dispatch body, the ChatService's new __init__/create_session/chat_stream shape, the lifespan's app.state.llm_factory, and the route layer's extended POST /api/chat/session that calls the new ChatService method. After this plan, picking ollama+model in the payload produces a working chat session backed by a per-session bound provider; picking openai/anthropic with a key behaves identically; missing keys surface the same ProbeError JSON the 4.2 frontend already consumes.

Purpose: This is the biggest architectural lift in the phase. The 4.2 model (singleton bound LLM at app startup, free-standing probe at route level, sync ChatService.create_session) becomes the 4.5 model (factory at app startup, per-session bound provider at create_session time, async ChatService.create_session that does the probe inline). The wire contract is preserved; the internal shape changes substantially.

Output: factory.build with match-dispatch on the four provider names (ollama/openai/anthropic; lmstudio is OUT of scope per the orchestrator narrowing — only three providers ship in 4.5); ChatService rewired to async create_session + per-session bound providers; lifespan rebuilt around the factory; routes.py POST /api/chat/session updated; mock_llm_provider conftest fixture re-spec'd against the new Protocol shape; existing test_session_probe.py rewires its single import path.
</objective>
