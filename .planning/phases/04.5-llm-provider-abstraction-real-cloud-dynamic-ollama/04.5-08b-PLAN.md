<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser DOM → `/api/chat/sessions` | The sidebar's session list is filtered server-side by Plan 06b; the frontend trusts the backend's per-user filter. A backend regression here would leak session metadata across users. |
| browser DOM → `/api/providers/refresh` | The refresh response writes into localStorage. A malicious response payload could in principle inject XSS via the model select if rendered without escaping — Chakra `<select>` and React's default text-content escaping mitigate. |
| browser DOM → `/api/providers/{provider}/test` | The api_key travels from localStorage to the test endpoint. Plan 06b's endpoint validates length + scrubs from logs. |
| browser DOM → DOM (third-party scripts) | localStorage api_key is plain-text; same trust model as Plan 07. Phase 8 CSP hardens this. |

Task 4 step 6 is the UAT gate that verifies the filter end-to-end. If the filter fails, Plan 06b is the fix surface — Plan 08b cannot patch this client-side. |
