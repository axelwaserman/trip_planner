# Phase 04.5 Plan 06b: Provider Discovery + Cloud Key Test + Per-User Sessions — Summary

The settings-page back end. Three new endpoints (POST /providers/refresh, POST
/providers/{provider}/test, GET /chat/sessions) plus a structural update to the
existing GET /api/providers (dynamic Ollama+LM Studio model lists, base_url per
entry). Sessions become per-user partitioned via a required `user_id` field on
`ChatService.create_session`. The plan ran in two halves: the previous executor
landed tasks 1-3 (Settings TTL, Pydantic models, ChatService partitioning,
factory.refresh_local_models, lifespan caches, three new endpoints) before
stalling on task 4 (#3212 stream-idle-timeout). The continuation executor wrote
all four test files (task 4) and wired GET /api/providers to the discovery
cache (task 5).

## Outcome

- `Settings.provider_models_cache_ttl_seconds = 60` is a tunable per CLAUDE.md's
  "tunable thresholds live on Settings" rule.
- `app/models.py` carries seven new Pydantic models: `ProviderInfo`,
  `ProviderRefreshEntry`, `ProviderRefreshResponse`, `ProviderTestRequest`,
  `ProviderTestResponse`, `ChatSessionInfo`, `ChatSessionsListResponse`.
- `ChatService.create_session(config, user_id)` requires `user_id` and stamps
  `_metadata[session_id]` with `user_id` + ISO `created_at`. The route layer
  passes `current_user.username` from the JWT.
- `ChatService.list_sessions_for_user(user_id)` filters `_metadata` by
  `user_id`, sorts newest-first by `created_at`, and returns `ChatSessionInfo`
  records with the first `HumanMessage` content truncated to 80 chars.
- `LLMProviderFactory.refresh_local_models()` runs Ollama and LM Studio
  `list_models` in parallel via `asyncio.gather(..., return_exceptions=True)`;
  unreachable daemons map to `None` so partial success doesn't crash the whole
  response (RESEARCH.md Pitfall 6).
- `app/api/main.py::lifespan` constructs the factory once and exposes
  `app.state.provider_models_cache` + `provider_models_cache_timestamps`
  (parallel dicts, per-entry TTL gating). `dependency_overrides` wires both
  `get_chat_service` and the new `get_llm_factory` from `app.state`.
- `POST /api/providers/refresh` (auth-protected): on stale entries, calls
  `factory.refresh_local_models()`; marks unreachable as
  `available=False, error="provider_unreachable"`; cache hit on TTL bypasses
  the daemon call entirely.
- `POST /api/providers/{provider}/test` (auth-protected): OpenAI →
  `GET /v1/models` (zero-cost, 401 → INVALID_API_KEY); Anthropic →
  `POST /v1/messages` with `max_tokens=1` (billable single token, 401 →
  INVALID_API_KEY, 429 → ok per researcher A3); ConnectError/timeout → 502
  with PROVIDER_UNREACHABLE; unknown providers (incl. local) → 400. The
  `api_key` never appears in any log line, response body, or exception path —
  enforced both by code and by a dedicated caplog-scan test.
- `GET /api/chat/sessions` (auth-protected): returns only the authenticated
  user's sessions via `chat_service.list_sessions_for_user(current_user.username)`.
  An integration test logs in as alice and bob and asserts each sees only
  their own sessions, never the other's.
- `GET /api/providers` (auth-protected) now reads ollama+lmstudio model lists
  from `app.state.provider_models_cache`. On first load (cache empty) it
  lazy-triggers a single `factory.refresh_local_models()` call. Cloud
  providers keep the curated static list from `Settings.get_available_providers`.
  Every entry gains `base_url`: from `Settings` for local, `None` for cloud.
  The wire shape is additive — the existing `ProviderSelector` frontend
  continues to work unchanged.

## Tasks Recap

### Task 1 (committed at f36b5c7) — Settings field + 6 Pydantic models

`Settings.provider_models_cache_ttl_seconds: int = 60` added; six new Pydantic
response/request models in `app/models.py` covering refresh/test/sessions wire

`ProviderTestRequest.api_key` carries a `field_validator` that strips

### Task 2 (committed at 9eb74ac) — ChatService user_id + factory.refresh_local_models + lifespan caches

`ChatService.create_session` signature gained a required `user_id: str` parameter;
`_metadata` stamps `user_id` + ISO `created_at` per session.
`ChatService.list_sessions_for_user(user_id)` walks `_metadata`, filters by
`user_id`, builds `ChatSessionInfo` records, and sorts newest-first.
`LLMProviderFactory.refresh_local_models()` instantiates Ollama + LM Studio
providers (with `model=""` since `list_models` doesn't consult `_model`) and
runs them through `asyncio.gather(..., return_exceptions=True)`, mapping
exceptions to `None`. `app/api/main.py::lifespan` initialises the two
parallel cache dicts on `app.state`.

### Task 3 (committed at 6ebc73f) — Three new endpoints + dependency_override wiring

`POST /api/providers/refresh` reads cache + timestamps, calls
`factory.refresh_local_models()` only for stale entries, builds
`ProviderRefreshEntry` per `_LOCAL_PROVIDER_NAMES = ("ollama", "lmstudio")`,
marks unreachable as `available=False, error="provider_unreachable"`.
`POST /api/providers/{provider}/test` dispatches on `provider` path-param to
explicit `_test_openai_key` / `_test_anthropic_key` helpers; both helpers
return `None` on success or a `ProbeError` that the route maps to 502
(PROVIDER_UNREACHABLE) or 400 (everything else). `GET /api/chat/sessions`
calls `chat_service.list_sessions_for_user(current_user.username)`.
`api/main.py` registers `dependency_overrides[get_llm_factory]` alongside
the existing `get_chat_service` override.

### Task 5 (committed at 4456461) — GET /api/providers dynamic discovery + base_url

`ProviderInfo` Pydantic model added (`available: bool`, `models: list[str]`,
`base_url: str | None`). `GET /api/providers` handler rewritten to:
- Read ollama + lmstudio models from `request.app.state.provider_models_cache`.
- Lazy-trigger `factory.refresh_local_models()` once when at least one local
  entry is missing from the cache (subsequent calls serve from cache).
- Keep curated static list for cloud providers (openai, anthropic) — no live
  cloud probe to avoid burning quota on every settings page load.
- Populate `base_url` from `Settings.{provider}_base_url` for local providers
  and `None` for cloud.

Six integration tests (`tests/integration/test_providers_endpoint.py`):
- Cache populated → response reflects cache without re-probing
  (asserts `refresh_local_models` is *not* called via a sentinel that raises).
- Cache empty → first call triggers single lazy refresh; second call serves
  from cache (call_count == 1 after both calls).
- Unreachable daemon (`refresh_local_models` returns `None`) → `models == []`,
  `available is False`.
- `base_url` is set to `Settings.ollama_base_url` / `Settings.lmstudio_base_url`
  for local; `None` for openai + anthropic.
- Cloud entries keep curated static list (`gpt-4o-mini`, `claude-3-5-sonnet-20241022`).
- 401 without auth.

## Deviations from Plan

None. The continuation executor took the plan's task 4 + task 5 specs as-written.

Two minor adjustments worth recording:

1. **`_LOCAL_PROVIDER_NAMES` constant moved up.** Task 5 needed the constant
   before the GET handler; the previous executor had defined it down in the
   POST /providers/refresh section. Moved to a shared "Plan 04.5-06b" header
   block above the GET handler. Single source of truth, no behavior change.
2. **Integration test fixture cleans up `_users_db`.** The plan's fixture
   spec added alice + bob without a teardown step. Without cleanup, sibling
   integration test modules (e.g., `test_auth_routes.py`) would see the
   alice/bob users leaking from `_users_db`. The fixture now `pop`s them on
   teardown so module ordering is irrelevant. Documented in the fixture
   docstring.
