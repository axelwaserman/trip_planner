<objective>
Implement OllamaProvider — the local provider that performs DYNAMIC model discovery via Ollama's GET /api/tags (ROADMAP success criterion #2). The provider satisfies the LLMProvider Protocol structurally; bind_tools delegates to langchain_ollama.ChatOllama with reasoning=True so the existing thinking-token path in chat.py keeps working. validate_config migrates the 4.2 probe semantics verbatim onto the provider class.

Purpose: Ollama is the foundation of "real" provider abstraction. Without dynamic discovery, the user can never see new models pulled via `ollama pull`. The migration from the free-standing probe_provider to a per-class validate_config + list_models is the architectural lift this plan delivers — the wire contract (ProbeErrorCode + ProbeError values) is preserved bit-for-bit so the 4.2 frontend continues to work.

Output: OllamaProvider class + its unit tests (replacing the Wave 0 skip stubs with real assertions). The factory wiring lands in Plan 06; the lifespan rewire lands in Plan 06; Plan 09 deletes the old free-standing probe.
</objective>
