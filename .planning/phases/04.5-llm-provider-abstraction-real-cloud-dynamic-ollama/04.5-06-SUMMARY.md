# Phase 04.5 Plan 06: Per-Session Provider Wiring — Summary

The biggest architectural lift of Phase 4.5: the 4.2 model (singleton bound LLM
at app startup, free-standing probe at the route layer, sync
`ChatService.create_session`) becomes the 4.5 model (factory at app startup,
per-session bound provider at create_session time, async
`ChatService.create_session` that does the probe inline). The 4.2 wire
contract on `POST /api/chat/session` is preserved bit-for-bit; the internal
shape changes substantially.

## Outcome

- `LLMProviderFactory.build` dispatches `match config.provider` to
  `OllamaProvider` / `OpenAIProvider` / `AnthropicProvider`; unknown names
  raise `ValueError`. D-08 precedence (payload `api_key` / `base_url` wins
  over `Settings`) resolves inline.
- `ChatService.__init__` now takes `(flight_client, factory: LLMProviderFactory)`;
  no startup-time `bind_tools`. `create_session` is `async`, builds a provider
  via the factory, awaits `validate_config`, calls `bind_tools`, stashes the
  `BoundProvider` keyed by `session_id`, and returns
  `(session_id, ProbeError | None)`. `chat_stream` reads from
  `self._bound_providers[session_id].astream(...)` — the thinking / tool_call /
  content / tool_result logic is preserved verbatim.
- Lifespan no longer calls `init_chat_model`. It constructs
  `LLMProviderFactory(settings)`, stashes it on `app.state.llm_factory`, and
  passes it to `ChatService(flight_client, factory=...)`.
- `POST /api/chat/session` payload extends to `{provider, model, base_url,
  api_key}` (D-24). The route builds a `SessionLLMConfig`, awaits
  `chat_service.create_session(config)`, and on `ProbeError` raises an
  `HTTPException` with the same status-code mapping as 4.2 (502 for
  `PROVIDER_UNREACHABLE`, 400 for everything else).
- `mock_llm_factory` conftest fixture lands alongside the legacy
  `mock_llm_provider`. Plan 09 deletes the legacy one when all callers
  migrate.
- Wave-0 protocol-conformance test activates: real `isinstance` assertions
  prove all three concrete providers structurally satisfy `LLMProvider` and
  none accidentally satisfy `BoundProvider`.

## Threat-register dispositions met

| Threat ID | Disposition | Evidence |
|-----------|-------------|----------|
| T-04.5-06-01 (provider name injection in factory.build) | mitigate | `match` against fixed Literal set + ValueError default branch + route-layer 400 on unknown name (defense in depth). |
| T-04.5-06-02 (api_key in route logs / HTTPException details) | mitigate | `ProbeError.message` and `.hint` are constructed without ever embedding `self._api_key`. The route raises `HTTPException(detail=probe_error.model_dump())` — no raw payload reaches logs. |
| T-04.5-06-03 (cross-session bound provider reuse) | mitigate | `self._bound_providers` keyed by `session_id` (UUID4 generated per session); two sessions with different keys get distinct dict entries. No global shared bound provider. |
| T-04.5-06-04 (slow validate_config blocking session create) | mitigate | OllamaProvider uses `httpx` timeout from `Settings.provider_probe_timeout_seconds` (1.5s default). OpenAI / Anthropic `validate_config` is presence-only — no HTTP. Worst case: 1.5s for unreachable Ollama. |
| T-04.5-06-05 (replay of POST /api/chat/session with stolen JWT) | accept | JWT auth gates the endpoint; stolen JWT replay sends keys to attacker's own session; impact bounded. v2 rotation deferred to Phase 5/8. |
| T-04.5-06-06 (search_flights tool injection via bind_tools) | accept | Tools list hardcoded to `[search_flights]` inside `ChatService.create_session` — user payload cannot inject. |

## Deviations from Plan

**One small deviation, type Rule 1 (auto-fix bug — test setup):** the
`test_session_probe.py::test_session_create_returns_400_when_cloud_key_missing`
test, when patched only via the module-level `app.config.settings`, did NOT
flip the factory's effective key. Reason: the lifespan-scoped
`LLMProviderFactory` captures the `Settings()` instance at app construction
time, NOT a live import-time reference. The plan's rewire instruction
(`monkeypatch.setattr("app.config.settings.openai_api_key", None, raising=False)`)
is necessary but not sufficient.

**Resolution:** also patch `factory._settings.openai_api_key = None`. Single
extra line; documented inline in the test. The fix preserves the test's
intent (4.2 wire contract: missing key → 400 `missing_api_key`) and the wire
copy is unchanged. Tracked here per the GSD deviation contract; no plan
substance change.

No other deviations — factory dispatch shape, ChatService rewire shape,
lifespan rewire, route rewire, and protocol conformance activation all match
PATTERNS.md / RESEARCH.md verbatim.
