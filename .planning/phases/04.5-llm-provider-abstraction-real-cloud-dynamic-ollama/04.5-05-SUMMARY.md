## Pitfalls handled

**Pitfall 2 — `ChatAnthropic` requires non-`None` `api_key` at construction.**
Unlike `langchain_openai.ChatOpenAI`, `langchain_anthropic.ChatAnthropic`
declares `anthropic_api_key` as a required Pydantic `SecretStr`. Passing
`api_key=None` raises a Pydantic `ValidationError` BEFORE user code can
intercept it — and the field path can leak into stack traces.

Defense in depth:
1. The factory ordering (Plan 06) guarantees
   `factory.build → validate_config → bind_tools` — the normal flow never
   reaches `bind_tools` with a missing key.
2. `bind_tools` itself contains `assert self._api_key is not None` as a
   precondition guard, converting any direct-caller misuse into a clean
   `AssertionError` instead of an SDK-internal `ValidationError`.
