<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser localStorage → backend POST /api/chat/session | API keys (cloud providers) leave localStorage and travel as JSON body field. Plan 02 SessionCreateRequest validators (length cap + SSRF guard) gate the inbound side. |
| browser localStorage → browser DOM | Plain-text storage; same-origin XSS could exfiltrate. Phase 8 CSP + sanitization is the v2 hardening (REQ-security-headers). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04.5-07-01 | Information Disclosure | api_key in localStorage | accept | v1 trust model — UI-SPEC §"Persistence affordance" mandates the user-facing helper text "Stored in this browser only — never on our server." Phase 5 introduces backend-encrypted storage; Phase 8 hardens CSP to prevent XSS exfiltration. |
| T-04.5-07-02 | Tampering | Legacy localStorage key migration could overwrite user data | mitigate | Migration is one-shot guarded — only fires when 'provider_settings' is absent AND 'llm_provider_config' is present. Repeated renders do not re-trigger. |
| T-04.5-07-03 | Information Disclosure | api_key in fetch logs (browser devtools) | accept | Standard browser-devtools visibility; same trust model as the password field on /login. v1 accepts. |
| T-04.5-07-04 | Tampering | base_url SSRF via localStorage poisoning | mitigate | Backend Plan 02 validator rejects non-allowlisted hosts at the route layer. Frontend cannot smuggle malicious base_url past the server-side check. |
</threat_model>
